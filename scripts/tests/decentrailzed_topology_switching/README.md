# Decentralized multi-ROV tracking: zero-holdover showcase

This package is a curated, reproducible showcase of vision-only decentralized parent switching for one leader ROV and three followers. It retains the local AprilTag-quality selector, PID parent tracker, per-follower unified collision/perception CBF-QP, and reduced-order ROV simulation.

## Showcase objective

Demonstrate dynamic parent switching **without any follower entering HOLD** during the selected 300 s run. The desired relay event is:

- Before 32 s: F1 tracks the Leader, F2 tracks the Leader, and F3 tracks F1.
- From 32 s through 52 s: F1's local Leader-tag detection is unavailable, while F1 can see F2 and F2 can still see the Leader. F1 switches to F2; F2 independently continues tracking the Leader; F3 continues tracking F1.
- Later: parent choices continue to change with local link quality and geometry. No follower uses a shared topology assignment or messages another ROV.

There is no fixed priority restriction and no cycle-prevention constraint. Directed cycles remain an acknowledged limitation of unrestricted independent selection.

## Curated simulation settings

| Parameter | Value | Purpose |
|---|---:|---|
| Duration | 300 s | One complete smooth figure-eight period |
| Sampling | 0.1 s | 3,000 control intervals |
| Leader path period | 300 s | Gentle, showcase-friendly turns |
| Camera horizontal FOV | 140 deg | Wide-angle forward camera |
| Camera vertical FOV | 100 deg | Wide vertical coverage |
| Camera maximum detection range | 22 m | Allows alternate parent tags to remain candidates |
| Camera minimum detection range | 1 m | Close-range exclusion |
| Selector enter threshold | 0.02 | Avoids rejecting otherwise valid low-but-usable links |
| Selector keep threshold | 0.012 | Retains links with small quality fluctuations |
| Desired local parent range | 5 m | Consistent relay spacing |
| Topology update period | 0.5 s | Parent selection rate |
| Switching penalty | 0.12 | Reduces unnecessary switching |
| Switching margin | 0.035 | Requires a meaningful quality improvement |
| Minimum dwell | 1 s | Anti-chatter setting |
| Static obstacles | 5 | Positioned near the perimeter of the formation corridor |

The obstacle arrangement leaves the relay sightlines usable in this showcase but still exercises the local collision detector and CBF. F1 has a scripted local detection mask: its view of F2 is unavailable before 32 s; its view of the Leader is unavailable from 32 s to 52 s. This represents a controlled occlusion / turn-induced tag-detection outage. These masks affect only F1's synthetic camera output, not another follower's state or decisions.

## Results from the included seed-4 run

- Zero holdover samples across all followers.
- 100% active parent-link fraction.
- Zero selected-link physical-visibility loss samples.
- Zero collision samples.
- Zero CBF-infeasible samples.
- Eight parent switches after initial assignments.
- During F1's Leader-link outage, F1 selects F2 for 100% of topology updates, while F2 selects Leader for 100% of its topology updates.
- No inter-agent messages, shared link-quality matrix, centralized optimizer call, or cycle-prevention rule.

The included metrics CSV and event log are generated by the simulation. `validate_showcase_results.py` checks the zero-holdover and safety showcase assertions.

## Run

```bash
pip install -r requirements.txt
python -m unittest -v
python run_decentralized_multi_rov_showcase.py --duration 300 --dt 0.1 --outdir results --seed 4
python validate_showcase_results.py results
```

## Important interpretation

This is a **showcase operating point**, not a claim that no-holdover behavior is guaranteed for arbitrary initial conditions, obstacle layouts, camera calibration, turbidity, leader maneuvers, or sensor failures. The 140 x 100 degree camera, 22 m range, slower leader path, carefully placed obstacles, and deliberate visibility schedule were selected to demonstrate uninterrupted local parent switching. A narrower real camera or more severe occlusion may correctly cause HOLD.

The fleet model is reduced-order kinematic/first-order velocity response, not a validated full hydrodynamic BlueROV2 model. Vision observations are synthetic geometric AprilTag observations; real image-level detector confidence, reprojection error, tag pixel area, underwater image degradation, and pose covariance are not simulated.

Collision and perception CBFs are per-follower velocity-reference filters. The simulator reports sampled clearance and QP feasibility, not a formal continuous-time safety proof. Cycle prevention is intentionally omitted: independent unrestricted selection can create cycles, and this is an open limitation of the no-communication formulation.
